# PROCESS.md — 50분 Ralph Loop 실행 절차

## 목표

이 문서는 코딩 에이전트가 50분 동안 반복적으로 구현·실행·수정하여 **Windows 실행 파일이 포함된 미니 뱀서 게임**을 만드는 작업 절차다.

작업 시작 전에 `AGENT.md`를 읽고, 충돌하는 판단이 있을 때는 `AGENT.md`의 범위 제한과 완료 정의를 우선한다.

---

## 기본 명령

환경에 맞게 Godot 실행 파일 이름을 먼저 찾는다.

```bash
godot --version
godot4 --version
```

프로젝트 실행 예시:

```bash
godot --path . --editor
```

헤드리스 검사 예시:

```bash
godot --headless --path . --quit
```

Windows 빌드 예시:

```bash
godot --headless --path . --export-release "Windows Desktop" build/MiniSurvivor.exe
```

---

# Phase 0 — 준비 및 범위 잠금, 0~5분

## Loop 0.1: 작업 디렉터리 확인

### 행동

- 새 Godot 4 프로젝트를 만든다.
- Compatibility 렌더러를 사용한다.
- 창 크기를 960×540으로 설정한다.
- 프로젝트 이름을 `MiniSurvivor`로 설정한다.
- `scenes`, `scripts`, `build` 폴더를 만든다.

### 검증

- `project.godot`가 존재한다.
- Godot이 프로젝트를 오류 없이 연다.

### 실패 시

- 프로젝트 생성 방식만 수정한다.
- 게임 기능 구현을 시작하지 않는다.

## Loop 0.2: 메인 씬 생성

### 행동

- 루트 노드 `Main`을 만든다.
- 배경을 어두운 색으로 설정한다.
- 메인 씬을 `scenes/Main.tscn`으로 저장한다.
- 프로젝트 메인 씬으로 지정한다.

### 완료 조건

- 실행 시 빈 게임 화면이 열린다.

# Phase 1 — 이동과 적, 5~15분

## Loop 1.1: 플레이어 생성

### 행동

- `CharacterBody2D` 기반 플레이어를 만든다.
- 엔진 내장 도형으로 플레이어를 표시한다.
- WASD와 방향키 입력을 받는다.
- 대각선 이동 속도를 정규화한다.
- 카메라를 플레이어 자식으로 둔다.

### 완료 조건

- 플레이어가 네 방향과 대각선으로 이동한다.
- 카메라가 플레이어를 따라간다.

### 검증

- 10초 동안 이동하며 오류가 없는지 확인한다.

## Loop 1.2: 적 생성

### 행동

- `CharacterBody2D` 기반 적을 만든다.
- 적은 플레이어를 향해 이동한다.
- 타이머로 적을 주기적으로 생성한다.
- 생성 위치는 플레이어 기준 화면 바깥 600~800 거리로 정한다.

### 완료 조건

- 적이 계속 생성된다.
- 모든 적이 플레이어 방향으로 이동한다.

### 실패 시 축소

- 별도 Enemy 씬이 문제면 런타임 코드에서 노드를 직접 생성한다.
- 복잡한 스폰 위치 계산을 포기하고 네 방향 중 무작위 위치에서 생성한다.

# Phase 2 — 전투 루프, 15~25분

## Loop 2.1: 자동 조준

### 행동

- 현재 존재하는 적 중 가장 가까운 적을 찾는다.
- 적이 없으면 발사하지 않는다.
- 무기 타이머가 끝나면 가장 가까운 적 방향으로 투사체를 생성한다.

### 완료 조건

- 플레이어 조작 없이 투사체가 자동 발사된다.
- 투사체가 적이 있는 방향으로 이동한다.

## Loop 2.2: 충돌과 피해

### 행동

- 플레이어, 적, 투사체에 충돌 레이어와 마스크를 설정한다.
- 투사체가 적에 닿으면 적 체력을 감소시킨다.
- 적 체력이 0 이하이면 제거한다.
- 투사체는 충돌 후 제거한다.

### 완료 조건

- 적을 실제로 처치할 수 있다.
- 처치 수가 증가한다.

## Loop 2.3: 플레이어 피격

### 행동

- 적이 플레이어와 접촉하면 피해를 준다.
- 연속 피해 방지를 위해 짧은 무적 시간을 적용한다.
- 체력 값을 HUD에서 확인할 수 있도록 변수와 신호를 준비한다.

### 완료 조건

- 적에게 닿으면 체력이 감소한다.
- 한 프레임에 체력이 모두 사라지지 않는다.

### 25분 게이트

아래가 모두 되면 다음 단계로 이동한다.

- 이동
- 적 생성
- 적 추적
- 자동 발사
- 적 처치
- 플레이어 피격

하나라도 안 되면 성장 시스템을 시작하지 않고 전투 루프를 먼저 고친다.

# Phase 3 — 경험치와 성장, 25~35분

## Loop 3.1: 경험치 획득

### 우선 구현

- 적 사망 시 플레이어 경험치를 즉시 증가시킨다.

### 선택 구현

- 시간이 충분할 때만 경험치 보석을 생성하고 가까이 가면 획득하게 만든다.

### 완료 조건

- 적 처치 후 경험치 수치가 증가한다.
- 필요 경험치에 도달하면 레벨이 오른다.

## Loop 3.2: 레벨업 일시 정지

### 행동

- 레벨업 시 게임 월드를 일시 정지한다.
- UI는 일시 정지 중에도 입력을 받도록 설정한다.
- 무작위 강화 2개를 표시한다.

### 완료 조건

- 레벨업 화면이 나타나는 동안 적과 투사체가 멈춘다.

## Loop 3.3: 강화 적용

### 우선순위 강화

1. 공격력 증가
2. 발사 간격 감소
3. 이동 속도 증가
4. 최대 체력 증가
5. 투사체 크기 증가

### 행동

- 버튼 또는 숫자키 `1`, `2`로 선택한다.
- 선택한 강화가 즉시 적용된다.
- UI를 닫고 게임을 재개한다.

### 완료 조건

- 최소 3종 강화가 실제 게임 수치에 반영된다.
- 같은 강화를 여러 번 선택할 수 있다.

### 실패 시 축소

- 카드 애니메이션 삭제
- 아이콘 삭제
- 설명을 한 줄 텍스트로 축소
- 마우스 버튼 대신 숫자키 선택 사용

# Phase 4 — HUD와 종료 루프, 35~42분

## Loop 4.1: HUD

### 표시 항목

- HP: 현재 / 최대
- Level
- EXP: 현재 / 필요
- 생존 시간
- 처치 수

### 완료 조건

- 플레이 중 값이 실시간으로 갱신된다.
- 텍스트가 화면 밖으로 나가지 않는다.

## Loop 4.2: 게임 오버

### 행동

- 체력이 0이 되면 게임 오버 상태로 전환한다.
- 게임 월드를 정지한다.
- 생존 시간과 처치 수를 표시한다.
- `R` 키 또는 재시작 버튼으로 현재 씬을 다시 불러온다.

### 완료 조건

- 사망 후 더 이상 전투가 진행되지 않는다.
- 재시작 후 모든 값이 초기화된다.

### 실패 시 축소

- 별도 게임 오버 씬을 만들지 않는다.
- 기존 HUD 위에 중앙 Label만 표시한다.

# Phase 5 — 통합 테스트, 42~47분

## Loop 5.1: 2분 플레이 테스트

다음 시나리오를 순서대로 테스트한다.

1. 게임 시작
2. 10초 이동
3. 적 5마리 이상 처치
4. 최소 1회 레벨업
5. 강화 선택
6. 일부러 적에게 접촉
7. 게임 오버 확인
8. 재시작 확인

발견한 문제는 `BLOCKER`, `MAJOR`, `MINOR`로 구분한다.

- BLOCKER: 실행 불가, 진행 불가, 크래시
- MAJOR: 핵심 루프 일부 미작동
- MINOR: UI 겹침, 밸런스, 시각 문제

수정 순서는 BLOCKER → MAJOR → MINOR다.

## Loop 5.2: 정적 정리

### 행동

- 사용하지 않는 임시 노드를 삭제한다.
- 디버그 출력이 과도하면 줄인다.
- 메인 씬 경로를 재확인한다.
- `README.md`를 작성한다.
- `BUILD_NOTES.md`를 준비한다.

### 금지

- 대규모 리팩터링
- 파일 구조 재편
- 새로운 시스템 추가

# Phase 6 — Windows 빌드, 47~50분

## Loop 6.1: Export Preset 확인

### 행동

- Windows Desktop 프리셋을 만든다.
- 출력 경로를 `build/MiniSurvivor.exe`로 지정한다.
- 임베드 PCK 또는 기본 설정 중 현재 환경에서 안정적인 방식을 선택한다.

## Loop 6.2: 빌드 실행

```bash
godot --headless --path . --export-release "Windows Desktop" build/MiniSurvivor.exe
```

### 빌드 성공 시

- `build/MiniSurvivor.exe` 존재 여부를 확인한다.
- 함께 생성된 `.pck`가 있다면 삭제하지 않는다.
- 가능하면 실행 파일을 직접 실행하여 시작 화면까지 확인한다.

### 빌드 실패 시

1. 오류 메시지를 읽는다.
2. 프리셋 이름과 출력 경로를 확인한다.
3. Export Template 누락 여부를 확인한다.
4. 한 번만 수정 후 재시도한다.
5. 여전히 실패하면 프로젝트를 손상시키지 말고 `BUILD_NOTES.md`에 해결 절차를 기록한다.

47분 이후에는 빌드 실패와 직접 관련 없는 코드를 수정하지 않는다.

# Ralph Loop 프롬프트

각 반복에서 에이전트는 아래 템플릿을 내부 작업 지시로 사용한다.

```text
현재 목표: [완료되지 않은 가장 중요한 기능 하나]
완료 조건: [관찰 가능한 결과]
제약: AGENT.md 범위 밖 기능 금지

1. 현재 프로젝트 상태를 확인한다.
2. 목표 달성에 필요한 최소 변경만 수행한다.
3. 실행 또는 헤드리스 검사를 한다.
4. 오류가 있으면 같은 루프에서 수정한다.
5. 완료 조건을 검증한다.
6. 변경 사항과 남은 BLOCKER를 기록한다.
```

# 상태 기록 형식

루프가 끝날 때마다 다음 형식으로 짧게 기록한다.

```text
[분:초] Loop X.Y
DONE: 완료한 기능
TEST: 실행한 검증
RESULT: 성공 / 실패
NEXT: 다음 단일 목표
BLOCKER: 없음 또는 문제 설명
```

예시:

```text
[18:40] Loop 2.1
DONE: 가장 가까운 적 자동 조준 및 투사체 생성
TEST: 에디터에서 적 10마리 생성 후 30초 실행
RESULT: 성공
NEXT: 투사체-적 충돌과 피해
BLOCKER: 없음
```

# 종료 보고 형식

```text
완료 상태: SUCCESS / PARTIAL
실행 파일: build/MiniSurvivor.exe
핵심 기능: 이동, 적 추적, 자동 공격, 성장, 게임 오버, 재시작
테스트 결과: [요약]
알려진 문제: [없음 또는 목록]
빌드 참고: [단일 exe / exe+pck / 수동 export 필요]
```

`SUCCESS`는 실제 실행 파일 생성과 핵심 루프 검증이 모두 완료되었을 때만 사용한다.
