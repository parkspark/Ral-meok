# AGENT.md — 50분 미니 뱀서 제작 에이전트 지침

## 1. 미션

50분 안에 **Windows에서 실행 가능한 파일이 포함된 미니 뱀서류 게임**을 완성한다.

최종 결과물은 다음을 만족해야 한다.

- Godot 프로젝트가 정상적으로 열린다.
- 플레이어가 이동할 수 있다.
- 적이 지속적으로 생성되어 플레이어를 추적한다.
- 무기가 자동으로 공격한다.
- 적 처치 시 경험치를 얻는다.
- 경험치가 차면 최소 2개 선택지 중 하나를 골라 강화한다.
- 체력이 0이 되면 게임 오버가 표시된다.
- 재시작할 수 있다.
- Windows 실행 파일 `.exe`가 빌드되어 있다.
- 외부 에셋이 없어도 실행 가능하다.

목표는 완성도 높은 게임이 아니라 **짧지만 처음부터 끝까지 플레이 가능한 수직 슬라이스**다.

---

## 2. 기술 스택

- 엔진: Godot 4.x
- 언어: GDScript
- 대상 플랫폼: Windows Desktop
- 렌더러: Compatibility
- 화면 크기: 960 × 540
- 그래픽: Polygon2D, ColorRect, Label, 기본 도형 등 엔진 내장 요소만 사용
- 오디오: 필수 아님
- 외부 플러그인, 외부 폰트, 외부 이미지, 애셋 스토어 사용 금지

Godot이 설치되어 있지 않거나 CLI 경로를 찾을 수 없다면 프로젝트 완성을 우선하고, 빌드 실패 원인을 `BUILD_NOTES.md`에 정확히 기록한다. 단, 가능한 모든 경로에서 실제 `.exe` 생성을 먼저 시도한다.

## 4. 최소 게임 디자인

### 플레이어

- 최대 체력: 100
- 이동 속도: 230
- 피격 무적 시간: 0.5초
- 기본 무기: 가장 가까운 적을 향해 자동 발사

### 적

- 기본 체력: 2
- 이동 속도: 70~110 사이
- 접촉 피해: 10
- 생성 간격: 0.7초
- 생성 위치: 화면 바깥쪽 원형 범위
- 시간이 지날수록 체력 또는 생성 속도를 소폭 증가

### 무기

- 발사 간격: 0.65초
- 투사체 피해: 1
- 투사체 수명: 1.5초
- 가장 가까운 적을 자동 조준

### 성장

레벨업 시 아래 강화 중 무작위 2개를 제시한다.

- 공격력 +1
- 발사 속도 +15%
- 이동 속도 +12%
- 최대 체력 +20 및 20 회복
- 투사체 크기 +20%

최소 3종만 구현되어도 완료로 인정한다.

### 종료 조건

- 체력이 0이 되면 게임 정지
- 생존 시간과 처치 수 표시
- `R` 키 또는 버튼으로 재시작

## 7. Ralph Loop 운영 규칙

각 루프는 아래 형식을 따른다.

1. 현재 가장 큰 미완성 항목 하나를 고른다.
2. 해당 항목만 구현한다.
3. 프로젝트를 실행하거나 정적 검사를 한다.
4. 오류가 있으면 즉시 수정한다.
5. 완료 조건을 확인한다.
6. 다음 항목으로 이동한다.

한 루프에서 여러 기능을 동시에 구현하지 않는다.

### 루프 종료 질문

매 루프가 끝날 때 내부적으로 아래를 확인한다.

- 게임이 이전보다 더 실행 가능한가?
- 새 오류가 생기지 않았는가?
- 지금 빌드해도 최소 플레이가 가능한가?
- 남은 시간에 비해 기능 범위가 과하지 않은가?

답이 아니오라면 새 기능을 추가하지 말고 현재 문제를 해결한다.

## 8. 시간 통제 규칙

- 0~5분: 프로젝트 생성, 기본 씬, 실행 확인
- 5~15분: 이동, 적 생성, 추적
- 15~25분: 자동 공격, 충돌, 처치
- 25~35분: 경험치, 레벨업, 강화
- 35~42분: HUD, 게임 오버, 재시작
- 42~47분: 통합 테스트, 버그 수정
- 47~50분: Windows 빌드 및 산출물 확인

### 강제 축소 규칙

- 15분 시점에 적 추적이 안 되면 단일 스크립트 구조로 전환한다.
- 25분 시점에 전투가 안 되면 경험치 드롭 오브젝트를 생략하고 처치 즉시 경험치를 준다.
- 35분 시점에 레벨업 UI가 안 되면 키보드 `1`, `2` 선택 방식으로 단순화한다.
- 42분 시점에 게임 오버가 안 되면 화면 중앙 Label과 `R` 재시작만 구현한다.
- 47분 이후에는 기능 추가를 금지하고 빌드만 수행한다.

## 9. 코드 규칙

- GDScript 경고보다 실행 오류를 우선 해결한다.
- 명확한 타입을 사용할 수 있으면 타입을 지정한다.
- 노드 경로는 `%UniqueName` 또는 `@onready`로 관리한다.
- 매 프레임 전체 노드를 반복 검색하지 않는다.
- 가장 가까운 적 탐색은 적 수가 적은 MVP 범위에서만 단순 순회한다.
- 오브젝트 풀링은 구현하지 않는다.
- 하드코딩된 수치는 상단 상수 또는 변수로 모은다.
- 함수는 가능한 한 한 가지 역할만 한다.
- 오류를 숨기는 빈 `catch`나 무의미한 조건문을 만들지 않는다.
- 임시 구현을 남길 경우 주석으로 이유를 기록한다.

## 10. 비주얼 규칙

외부 리소스 없이 아래 색상 구분만 명확히 한다.

- 플레이어: 청록색 원 또는 다각형
- 적: 붉은색 원
- 투사체: 노란색 작은 원
- 경험치: 녹색 작은 다이아몬드. 생략 시 표시하지 않아도 됨
- 배경: 어두운 회색
- UI: 흰색 텍스트와 반투명 검정 패널

가독성이 화려함보다 중요하다.

## 11. 테스트 체크리스트

빌드 전 아래를 직접 확인한다.

- [ ] 프로젝트가 오류 없이 시작된다.
- [ ] WASD와 방향키 중 하나 이상으로 이동된다.
- [ ] 적이 플레이어 주변에서 생성된다.
- [ ] 적이 플레이어를 추적한다.
- [ ] 투사체가 자동 발사된다.
- [ ] 투사체가 적에게 피해를 준다.
- [ ] 적이 죽고 처치 수가 증가한다.
- [ ] 경험치가 증가한다.
- [ ] 레벨업 시 게임이 일시 정지된다.
- [ ] 강화 선택 후 게임이 재개된다.
- [ ] 적 접촉 시 플레이어 체력이 감소한다.
- [ ] 체력 0에서 게임 오버가 표시된다.
- [ ] 재시작이 동작한다.
- [ ] 실행 파일이 생성된다.
- [ ] 실행 파일을 프로젝트 외부에서 직접 실행할 수 있다.

## 12. 빌드 규칙

가능하면 다음 방식으로 Windows 빌드를 만든다.

```bash
godot --headless --path . --export-release "Windows Desktop" build/MiniSurvivor.exe
```

환경에 따라 실행 파일 이름이 `godot4`, `Godot`, 또는 절대 경로일 수 있다.

빌드 전 확인 사항:

- `export_presets.cfg` 존재
- Windows Desktop 프리셋 존재
- 메인 씬 지정
- `build/` 폴더 존재
- 내보내기 템플릿 설치 여부 확인

빌드에 실패하면 에러 메시지를 보존하고 `BUILD_NOTES.md`에 다음을 기록한다.

- 실행한 명령
- 발생한 오류
- 필요한 수동 조치
- 프로젝트 자체 실행 여부

## 13. 최종 산출물

완료 시 아래 파일이 존재해야 한다.

```text
MiniSurvivor/
├─ project.godot
├─ export_presets.cfg
├─ scenes/
├─ scripts/
├─ build/
│  └─ MiniSurvivor.exe
├─ README.md
└─ BUILD_NOTES.md
```

`README.md`에는 다음만 간단히 적는다.

- 게임 설명
- 조작법
- 실행 방법
- 구현된 강화 목록
- 알려진 제한사항

## 14. 완료 정의

다음 문장이 모두 참이면 작업을 종료한다.

- 사용자가 압축을 풀고 `.exe`를 실행할 수 있다.
- 최소 1분 이상 플레이가 가능하다.
- 이동, 추적, 자동 공격, 성장, 사망, 재시작의 전체 루프가 연결되어 있다.
- 치명적인 오류가 없다.
- 추가 기능보다 안정적인 빌드가 우선되었다.

완료 조건을 충족하면 리팩터링이나 기능 추가를 하지 않고 즉시 종료한다.
